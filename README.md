# Inkdesk 0.1 · 写作工作台

独立的 Apple Silicon macOS 应用。项目在 `/Users/jin/Documents/Dev/inkdesk`。内容仓库（Content_OS）可在设置中选择；也可用 `vault.json` 或 `INKDESK_VAULT` 指定。开发时指向测试目录即可。

打开 `dist-v4/Inkdesk-darwin-arm64/Inkdesk.app`。左侧选择账号和草稿，正文自动保存，右侧按需调用 Cursor 或 Codex。无需另购 API。

## 0.4 当前框架

账号设定固定为五个 Tab：定位与读者、表达与边界、经历与范文、数据与实验、迭代记录。前四个内容模块统一写入每个账号的 `00_Profile/Account_Model.md`。旧 Profile 文档保留为只读历史资料，不再同时作为规则生效；0.3 的文件勾选和文件级精简方案已由这个模型取代。

AI 只可建议替换现有模块内容，不能增加模块或文件。每次迭代附有来源和差异，采纳前可修改，历史模型可恢复。数据与实验保留少量观察和下一步验证，不把单篇表现视为因果或承诺涨粉。

项目素材统一用卡片展示，点击后在右侧预览。对话框支持直接上传，以及通过 `@` 或「项目文件」在光标处插入文件标签。预览中选定文字可以引用对应文件行；正文选段可以通过「引用选段」插入标签。标签与自由文字交错排列，随各自对话草稿保存，也保留在已发送记录中。

有文件标签时，本次只读取标签指定的文件/行；没有文件标签时沿用项目勾选资料。「改写标签选段」支持多个不重叠选段，先预览差异，接受后只替换相应位置。正文已变化的选段会被判定为过期，不自动套用。标签可以用退格键删除。

发布热力图为今天增加描边及日期提示，悬停或键盘聚焦查看文章，无需点击。「文章涨粉合计」仅汇总文章 YAML 的涨粉记录，不是账号净增粉丝，也不是工作台估算。

## 0.3 历史功能

- **整个 Profile 的统一管理**：递归列出定位、Author_DNA、结构、范文与数据规律，逐文件编辑、保存前校验冲突并保留旧版。复选框控制哪些文件参与日常写作。
- **精简与持续迭代**：「预览精简方案」将日常核心收敛到定位、语言、边界、迭代观察四份文件，其他文件继续保留。已有用词与句式偏好纳入边界。方案需要在界面采纳才写入文件。「根据新文章和数据迭代」读取最新 Profile 和最近 12 篇本账号草稿/归档、原始 YAML；每篇或文件提供前 3000 字并标记省略。结果包含文件差异、来源与理由，可编辑后采纳或保留原设定。单篇数据不推断因果。
- **草稿项目素材**：每篇草稿单独上传参考文件。支持 UTF-8 文本/Markdown/CSV/JSON、Word、PDF（扫描页自动 OCR）、图片文字识别。原文件复制到 `00_wiki/_data/raw/projects/文章ID/files`；提取文本与引用开关放在 `_system/inkdesk/projects/文章ID`。启用的素材全文加入该项目的 Agent 请求，绝不串到其他项目。单文件 40MB，单次参考文字总计超过 30000 字时要求减少启用文件，不静默截断。无法解析的文件保留并明确标记，不能启用 AI 引用。图片 OCR 不理解完整图形语义；必要时补充文字说明。
- **归档表格**：按发布时间排序，显示标题、日期、体裁、观看/阅读和收藏，支持查看全文和原有版本记录。
- **发布热力图**：按年显示每日发布次数，点击日期查看文章；统计发布篇数、发布天数与平均每周频率。只读取 YAML 发布时间，空日期、无效日期和未来日期不计入实际发布。

仅在点击发送或迭代时，将界面注明的资料提供给所选 Cursor/Codex。不会后台上传资料；没有实际检索来源时，事实检查仍需保留「待核实」。

## 0.2 已有功能

1. 数据概览直接读取各账号 `03_Archive/**/*.md` 的 YAML。阅读取「观看量」，兼容「阅读」；空值显示为未知。保留发布时间、未知字段和 YAML 注释。
2. 我的草稿读取 `02_Drafts`，支持命名版本、自动保存前快照、恢复版本。旧 `.ai-v1.md` 等同名版本纳入原文章版本列表。素材库读取 `00_wiki`，支持查看、创建、关联草稿、插入选段或素材链接。
3. 新图片保存为 `Attachment/文章名/file-YYYYMMDDHHmmssSSS.ext`，重名增加空格序号。Markdown 保存 Obsidian 图片链接。改名时将当前文章所用图片复制到新文章目录，旧图片保留以维持历史版本及其他文章的引用。
4. 每篇文章有多个独立对话，可创建和切换。请求发出时绑定文章和对话，回复不会串到刚切换的新对话。
5. 正文、图片、人设和素材使用 Content_OS 目录。工作台专用关系数据放在 `_system/inkdesk`，JSON 不再作为正文数据库。
6. 账号人设页展示简化写作约定和原始 Persona_Doc。AI 使用勾选的账号文件及本次文章、对话、启用的项目素材，不再叠加整套旧规则。保存约定会备份上一个版本。接受/拒绝修改记录留在本机，不自动发送给 AI。
7. 无 Markdown 导出按钮。定稿弹出二次确认，确认后把当前文件从 `02_Drafts` 移至对应 `03_Archive`，保留版本、对话、素材关系；同名冲突不会覆盖。此操作是本地归档，不自动发布到平台、不自动填写平台发布时间。

## 存储结构

```text
Content_OS/
  <账号文件夹>/                     # 设置中选择或新建；侧边栏按此切换
    00_Profile/
      Persona_Doc.md
      Writing_Contract.md
      Account_Model.md
    01_Topics/
    02_Drafts/**/*.md
    03_Archive/**/*.md
  00_wiki/
    _data/raw/inbox/
  Attachment/文章名/file-时间戳.ext
  _system/inkdesk/
    accounts.json                   # 已注册账号列表
    index.json
    ...
```

内容仓库在设置中选择。账号对应仓库内文件夹：可「选择文件夹」注册，或「新建账号」自动创建 Profile / Topics / Drafts / Archive 四个目录。旧版 `金奇_AI` / `金奇_Dev` 会被自动识别。

Content_OS 路径优先取自设置中用户选择的仓库（写入 `workspace.json` 的 `vaultPath`）；也可用 `vault.json` 或环境变量 `INKDESK_VAULT` / `INKDESK_DATA`。测试常用临时目录。

打包版工作区设置在 macOS Application Support 的 `inkdesk/workspace-v2` 下。第一次运行会从旧 `workspace` 复制旧 JSON 与图片，迁移前保留 `.v1-backup`；旧应用数据保留。实际路径可在「设置 → 本地数据」查看。

外部修改与编辑器内容冲突时停止覆盖。点击「刷新本地数据」后，可以把未保存内容备份到 recovery，再读取磁盘版本。无法解析的 YAML 文件在设置页列出错误，不会自动覆盖。

## 写作闭环

素材 → 自己写草稿 → 按需讨论、核查和精修 → 选择版本 → 确认定稿 → 阅读归档 YAML 数据 → 主动把一条经验更新到写作约定。不要求每篇逐项打卡。

公众号排版可一键复制富文本，归档文章也能复制。本地图片会生成上传占位提示，需要在公众号编辑器上传；剪贴板已测试，公众号网页实际粘贴效果尚未验证。

核查没有真实检索来源时必须标为待核实。本版未增加自动联网检索或历史修改样例外发。Cursor / Codex 需要先在 CLI 登录；编辑、版本、素材与归档不依赖 AI 登录。

常见 Markdown、表格、Obsidian 图片和笔记链接可以使用。插件专属语法不保证视觉渲染；只打开或切页不会重写原文。

## 开发与验证

```sh
npm ci
npm run build
npm start
npm test
npm run test:ui
npm run package:mac
```

`npm test` 覆盖 YAML 保留、空值、图片路径、改名、版本、对话、归档冲突、外部修改保护、素材和约定；`npm run test:ui` 覆盖富文本保存与复制、润色接受/拒绝、过期建议保护，以及项目素材上传和实际请求隔离、人设文件编辑、精简/迭代采纳、归档表格与热力图。测试使用本地模拟 Agent，不调用真实 AI。

`node real-vault-smoke.cjs` 在指定 Content_OS 目录上浏览页面并比对现有 Markdown 哈希；生成页面截图。`node live-agent.cjs` 会实际调用 Agent，不属于默认测试。

原生素材读取器源码：`ReferenceReader.swift`。重新编译命令：`xcrun swiftc ReferenceReader.swift -o assets/reference-reader -framework AppKit -framework Vision -framework PDFKit`。打包时作为独立资源携带，不需要用户安装 Swift。
